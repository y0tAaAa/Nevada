# Тесты Nevada

Самописные тесты без внешних фреймворков: каждый файл — обычный скрипт,
который печатает `[OK ]` / `[FAIL]` по проверкам и в конце строку `ИТОГ:`.
Код выхода 0 = всё прошло.

## Запуск

```bash
python tests/run_tests.py            # офлайн-тесты (по умолчанию)
python tests/run_tests.py --live     # живые: сеть, токены Groq, окна
python tests/run_tests.py --all      # всё подряд
python tests/run_tests.py test_skills.py test_tools.py   # выборочно
```

Если зависимости установлены не в основной Python, а в отдельную папку:

```bash
set NEVADA_TEST_DEPS=C:\путь\к\deps
```

## Офлайн-тесты

Не требуют сети, ключей и не трогают рабочий стол — можно гонять после любой правки.

| Файл | Что защищает |
|------|--------------|
| `test_provider_config.py` | Переключение провайдера модели через `.env`: Groq / NVIDIA NIM / свой endpoint. Проверяет на временных `.env`, рабочий возвращает на место |
| `test_agent_loop.py` | Агентный цикл: инструмент выполняется один раз, его реальный вывод возвращается в модель, XML вызова скрыт от пользователя, служебные блоки не попадают в память |
| `test_fact_guard.py` | Страж выдумок: модель не может назвать показатели системы, не вызвав инструменты. Внутри — реальный текст, которым Nevada однажды соврала |
| `test_confirm_gate.py` | Подтверждение опасных действий. Ключевая проверка: модель сама подставляет `"confirm": true` — и всё равно не проходит без клика пользователя |
| `test_skills.py` | Навыки: разбор markdown, поиск по триггерам с учётом падежей, живая перезагрузка папки |
| `test_app_tool.py` | Белый список программ, перечисление окон, запрет печатать «вслепую» без указания окна |
| `test_tools.py` | Инструменты shell/file: деструктивные операции без подтверждения не выполняются |
| `test_fixes.py` | Очистка ответа от tool-тегов перед озвучкой, фильтр галлюцинаций Whisper |
| `test_worker_dedup.py` | `AgentWorker` не выполняет инструменты сам (иначе они отработали бы дважды) |
| `test_wiring.py` | Сборка UI: ловит ошибки проводки вроде «нет атрибута confirm_broker» до запуска на экране |
| `test_ui_layout.py` | Пузыри сообщений не обрезаются, лента прокручивается, HUD выдерживает cooldown |

## Почему так, а не pytest

Тесты писались по ходу отладки и проверяют поведение целиком — от разбора HTML
до реального переключения окон Windows. Формат «скрипт, который печатает итог»
позволяет запускать любой из них по отдельности и читать вывод как отчёт.
Перейти на pytest можно в любой момент: проверки уже изолированы.

Раннер требует от каждого теста строку `ИТОГ:` — иначе считает его провалившимся.
Это защита от ложного «зелёного»: обрезанный или молча упавший файл тоже
завершается с кодом 0.
